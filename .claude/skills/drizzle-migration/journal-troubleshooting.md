# Journal Troubleshooting

Common issues with the Drizzle Kit migration journal and environment state.

## Migration System Overview

```
Schema files (backend/src/db/schema/*.ts)
        │ drizzle-kit generate
        ▼
Migration SQL (backend/drizzle/NNNN_*.sql)
Snapshot JSON (backend/drizzle/meta/NNNN_snapshot.json)
Journal JSON  (backend/drizzle/meta/_journal.json)
        │ drizzle-kit migrate
        ▼
PostgreSQL (__drizzle_migrations tracking table)
```

**Journal**: `backend/drizzle/meta/_journal.json` — version 7 format, currently 8 entries (0000-0007)
**Tracking table**: `__drizzle_migrations` in PostgreSQL — records hash + timestamp of each applied migration

## Common Error Scenarios

### "relation already exists"

**Cause**: Table was created by a manual migration, but the Drizzle journal doesn't know about it.

**Diagnosis**:
```bash
cd backend
npm run db:check-tables     # What tables exist in DB?
npm run db:check-migrations # What does __drizzle_migrations show?
```

**Fix**: Run the reconciliation script:
```bash
cd backend && npm run db:reconcile
```
This inserts the 0007 migration hash into `__drizzle_migrations`, telling Drizzle Kit "this migration was already applied."

### "Schema drift detected" in CI

**Cause**: Schema files were modified but `npm run db:generate` wasn't run (or generated files weren't committed).

**How CI detects it**: The `quality-gates.yml` job runs `pnpm db:generate` and checks if any files in `backend/drizzle/` changed:
```yaml
- name: Check for uncommitted schema drift
  run: |
    pnpm db:generate 2>&1 || true
    if [ -n "$(git diff --name-only backend/drizzle/)" ]; then
      echo "::error::Schema drift detected"
      exit 1
    fi
```

**Fix**:
```bash
cd backend && npm run db:generate
# Review the generated SQL
git add backend/drizzle/
git commit -m "chore(db): generate migration for schema changes"
```

### Migration skipped silently

**Cause**: The SQL file was modified after generation, changing its SHA-256 hash. Drizzle Kit compares hashes and may skip or re-run.

**Fix**: Never modify generated SQL after `db:generate`. If you need to change the SQL:
1. Delete the generated files (SQL + snapshot + journal entry)
2. Re-run `npm run db:generate`
3. If you need custom SQL (e.g., `CONCURRENTLY`), use a separate one-time script in `backend/scripts/`

### "column does not exist" at runtime

**Cause**: Migration wasn't applied in this environment.

**Fix**:
```bash
cd backend && npm run db:migrate
```

### Type mismatch at runtime (JSONB columns)

**Cause**: The TypeScript interface in the schema file changed, but the Zod schema in `jsonb-schemas.ts` wasn't updated (or vice versa).

**Fix**: Both must stay in sync:
- Schema interface: `backend/src/db/schema/*.schema.ts` (the `.$type<T>()` annotation)
- Zod runtime schema: `backend/src/db/jsonb-schemas.ts`
- Use `.passthrough()` on Zod schemas for backward compat with existing rows

### CI blocks "orphaned manual migrations"

**Cause**: A `.sql` file was placed in `backend/drizzle/migrations/` instead of being generated by Drizzle Kit.

**Detection**:
```yaml
- name: No orphaned manual migrations
  run: |
    if ls backend/drizzle/migrations/*.sql 2>/dev/null; then
      echo "::error::Manual migrations found"
      exit 1
    fi
```

**Fix**: All migrations must go through `npm run db:generate`. If you need custom SQL:
- Add it as a one-time script in `backend/scripts/`
- Or use Drizzle Kit's custom SQL escape hatch

## Environment State Matrix

| Environment | Expected State | Migration Path |
|---|---|---|
| **Fresh DB** (new dev, CI) | Empty | `npm run db:migrate` applies 0000-0007 |
| **Existing DB** (had manual SQL) | Tables from manual migrations exist | `npm run db:reconcile` first, then `npm run db:migrate` |
| **CI test DB** | Fresh PostgreSQL 15 container | `npm run db:migrate` in quality-gates job |
| **Production** | All 12 tables, all indexes | `npm run db:migrate` in deploy pipeline (no dry-run currently!) |

## Utility Commands

| Command | What It Does |
|---|---|
| `npm run db:generate` | Diff schema files vs latest snapshot → produce SQL |
| `npm run db:migrate` | Apply pending migrations to DB |
| `npm run db:reconcile` | Insert 0007 hash into `__drizzle_migrations` |
| `npm run db:check-tables` | List all tables in the connected database |
| `npm run db:check-migrations` | Show all entries in `__drizzle_migrations` |
| `npm run db:studio` | Open Drizzle Studio GUI for visual inspection |

## Next Migration Will Be 0008

The next migration generated by Drizzle Kit will be index 8, tag `0008_*`. It will diff the current schema files against the `0007_snapshot.json` and produce SQL for any differences.

If the next migration looks unexpectedly large, it may be because:
1. Schema files were modified without generating migrations earlier
2. The snapshot is out of sync with the actual DB state
3. A new schema file was added to `backend/src/db/schema/` but the barrel export wasn't updated

Always review generated SQL before committing.
